### 程序解释

一、开发背景与定位
本程序由刘春潮于2024年4月至2025年4月独立开发，是六足机器人控制系统的启动核心。代码逻辑参考了宇树蓝皮书的状态机设计框架，以及MIT经典动力学方法（如模型预测控制MPC、全身控制WBC、落足点规划等），但具体实现与MIT算法存在显著差异，还参考了yyshuo的开源代码的MPC和地形估计部分，需结合刘春潮的MPC/WBC论文深入理解细节。

由于程序大量使用指针、类、派生类及对象，框架耦合度较高，因此仅适合具备1年以上C++开发经验且算法基础扎实的开发者维护。


二、核心功能与依赖
程序的核心目标是启动并运行机器人控制系统，实现运动控制、状态管理、传感器数据处理及外部交互。其依赖的关键模块与库包括：
- 控制框架：`ControlFrame`（控制主框架）、`CtrlComponents`（控制组件集合，整合核心参数与状态）；
- 步态与平衡：`WaveGenerator`（步态波形生成器，负责周期性步态信号输出）、`BalanceCtrl`（平衡控制模块，维持机器人稳定）；
- 接口模块：`KeyBoard`（键盘输入处理，接收用户指令）、`IOROS`（ROS接口，用于仿真环境数据收发）、`IOSDK`（硬件SDK接口，适配真实机器人通信）；
- 算法工具：`OsqpMpcTest`（MPC求解器测试模块）、`imu`（IMU传感器数据处理）；
- 系统库：线程（`thread`）、信号处理（`signal`）、实时调度（`sched`）等，支撑多任务并行与实时性保障。


三、关键结构与运行流程
1. 预处理与辅助定义
程序首先包含各模块头文件，确保控制逻辑、接口、算法等组件可被调用。同时定义`RosTopicMsgPub`类（仅仿真模式生效），用于将机器人状态（如质心位置、速度、姿态）通过ROS话题发布，支持`double`数组及Eigen矩阵类型的消息格式，方便外部可视化工具（如RViz）实时监控。

2. 实时性与安全机制
- 实时性保障：`setProcessScheduler`函数将进程调度策略设为`SCHED_FIFO`（实时先进先出），并配置最高优先级，确保控制逻辑在实时环境中优先执行，满足机器人控制对实时性的要求（控制循环频率≥1kHz）。
- 安全退出：`ShutDown`函数捕获`SIGINT`信号（Ctrl+C），将`running`标志设为`false`，实现程序优雅退出，避免强制终止导致的硬件异常（如电机锁死）。

3. 主函数（`main`）核心流程
- **环境与接口初始化**：调用`setProcessScheduler`配置实时调度，初始化ROS节点（`lcc2423f`）；根据宏`USE_A_REAL_HEXAPOD`选择接口类型（真实机器人用`IOSDK`，仿真用`IOROS`），并绑定对应控制平台（`REALROBOT`或`GAZEBO`）。
- **控制组件配置**：创建`CtrlComponents`对象（`ctrlComp`），设置时间步长`dt`（默认0.003秒，约333Hz，可根据硬件性能调整）、运行标志（绑定`running`）；加载六足机器人模型（`SixLegDogRobot`），提供运动学与动力学参数支持；初始化`WaveGenerator`（步态生成器），根据宏`GAIT_DEFAULT_TROT`（trot步态）、`GAIT_DEFAULT_WALK`（行走步态）、`GAIT_DEFAULT_CLAW`（爪状步态）配置周期、占空比、相位偏移等参数，且仿真与真实机器人参数适配硬件特性（如真实机器人步态周期更长）。
- **控制框架启动**：初始化`ControlFrame`（控制框架），整合`ctrlComp`组件；绑定`SIGINT`信号到`ShutDown`函数，确保安全退出。
- **分模式运行**：
  - 仿真模式（`USE_A_REAL_HEXAPOD == false`）：循环调用`ctrlFrame.run()`执行控制逻辑（状态机切换、步态生成、平衡控制等），同时通过`RosTopicMsgPub`发布质心位置（`COM`）、速度（`VEL`）、姿态（`RPY`）等状态到ROS话题，支持外部监控。
  - 真实机器人模式（`USE_A_REAL_HEXAPOD == true`）：启动多线程并行处理——`spi_can_run`线程处理电机通信（使能/关闭、抖动抑制、数据发送），`imu_recv`线程周期性读取IMU数据，`main_thread`线程执行核心控制逻辑，`save_data2txt`线程（需`TXT_FLAGE`启用）保存关键数据（电机力矩、姿态、足端力等）到文本文件，用于调试分析。


四、关键特性与模块协同
- **多模式适配**：通过宏定义实现仿真/真实环境、多种步态模式的快速切换，增强系统灵活性。
- **实时性优化**：实时进程调度、多线程并行、固定时间步长结合，确保控制延迟≤10ms，满足动态控制需求。
- **模块协同**：依赖`FSM`模块实现状态切换，`Gait`模块提供步态信号，`interface`模块处理输入输出，`common`模块提供模型与工具函数，形成完整控制闭环。


### 六足机器人控制

使用该程序控制六足机器人需遵循“环境准备→编译启动→状态切换→动作控制”的流程，结合仿真或真实硬件特性，通过键盘指令与实时监控完成操作，具体步骤如下：


一、环境准备
1. 硬件环境（真实机器人）
- 核心组件连接：确保18个关节电机（每足3个）、IMU传感器（如MPU6050，用于姿态检测）、主控板（如NVIDIA Jetson或x86工控机）、电源模块连接无误。
- 通信验证：通过`interface/serial_port.cpp`或`IOSDK`接口检查电机编码器数据、IMU数据传输是否正常（可使用`minicom`或自定义脚本提前验证串口/CAN通信）。

2. 软件环境（通用）
- 依赖安装：需配备Ubuntu 20.04+操作系统，安装ROS Noetic+、Eigen 3.3.7+、OSQP 0.6.0+等依赖库；真实机器人建议安装实时内核，提升控制实时性。
- 代码部署：将程序置于ROS工作空间的`src`目录（如`~/catkin_ws/src/lcc_hexapod`），确保CMakeLists.txt正确配置依赖（参考编译脚本）。


二、编译与启动
1. 编译工程
```bash
cd ~/catkin_ws  # 进入ROS工作空间
catkin_make     # 首次编译需下载依赖，耗时较长
source devel/setup.bash  # 加载环境变量
```

2. 启动程序
- 仿真模式（Gazebo）：先启动仿真环境，再运行控制程序：
  ```bash
  roslaunch lcc_hexapod gazebo.launch  # 启动六足机器人仿真环境
  rosrun lcc_hexapod main              # 启动控制程序（默认仿真模式）
  ```
- 真实机器人模式：需root权限确保实时调度生效：
  ```bash
  sudo su  # 切换至root权限
  source devel/setup.bash
  rosrun lcc_hexapod main  # 自动启用真实硬件接口
  ```


 三、核心操作流程
程序通过键盘指令触发状态机切换，实现机器人从初始化到运动的全流程控制，关键步骤如下：

1. 初始化与安全检查
- 退出闭环模式：启动程序后输入`o`（小写字母o），电机退出闭环控制（无动力输出），避免误动作。
- 传感器验证：
  - 仿真模式：通过`rostopic echo /RPY`查看姿态数据，确认IMU仿真数据正常（roll/pitch/yaw接近0）。
  - 真实模式：观察终端输出的`rotMatToRPY`数据，确认IMU姿态稳定（无剧烈波动）。

2. 闭环控制与姿态初始化
- 激活闭环控制：输入`p`（小写字母p），电机进入闭环模式（PID控制生效），机器人保持当前姿态。
- 机械校准：输入`[`（左方括号）启动抖动抑制算法，消除关节机械间隙（终端会打印电机目标角度，确认无异常）。
- 姿态调整：
  - 输入`c`：机器人进入蹲下状态（关节角度固定为安全值）。
  - 输入`2`：从蹲下切换至站立状态（通过逆运动学计算足端位置，缓慢起身）。
  - 输入`3`：进入自由站立模式（平衡控制算法启动，通过WBC调整关节力，维持机身水平）。

3. 步态控制与运动
- 启动动力学控制：输入`7`激活WBC（全身动力学控制），机器人可根据步态指令调整足端轨迹与力分布。
- 切换步态：输入`.`（小数点），从站立模式切换至预设步态（根据`GAIT_DEFAULT_*`宏定义，默认可能为trot步态）；如需修改步态参数（周期、占空比等），需调整`WaveGenerator`初始化代码后重新编译。
- 运动控制：通过键盘方向键（`KeyBoard`模块支持）或ROS话题（`/cmd_vel`）发送速度指令，机器人将通过MPC算法规划轨迹，实现前进、后退、转向（具体指令映射参考`KeyBoard.cpp`）。

4. 停止与退出
- 紧急停止：输入`1`进入被动状态，电机关闭动力，机器人瘫软。
- 数据保存：输入`T`（大写字母T），将当前状态（电机力矩、质心位置、足端力等）保存至`CoT_motor_t.txt`等文件，用于后续分析。
- 安全退出：按`Ctrl+C`触发`ShutDown`函数，程序自动关闭电机动力并退出（禁止直接kill进程，避免电机锁死）。


四、数据监控与注意事项
- 数据监控：
  - 仿真模式：通过ROS话题实时查看状态（`rostopic echo /COM`查看质心位置、`/VEL`查看速度、`/RPY`查看姿态）。
  - 真实模式：通过程序生成的txt文件分析数据（如`RPY_act_des_slopDegree.txt`记录实际与期望姿态，`foot_forceZ_forceSum.txt`记录足端力）。
- 注意事项：
  - 实时性：真实机器人模式需确保CPU利用率≤70%（用`htop`监控），避免控制周期紊乱。
  - 硬件保护：电机温度超过60℃时会自动降力，需暂停控制防止损坏。
  - 参数适配：不同机械结构需修改`SixLegDogRobot.cpp`中的模型参数，避免关节卡顿。


### 实物操作指南

真实六足机器人的启动需严格遵循硬件检查、状态切换的流程，确保操作安全与控制有效，具体步骤如下：


一、系统启动与硬件检查
1. **程序编译与运行**  
   进入ROS工作空间，执行以下命令编译并启动控制程序：
   ```bash
   cd /home/lcc/1_noetic_ws/20250416_ws_lcc_so
   catkin_make  # 编译工程，确保无报错
   source devel/setup.bash  # 加载环境变量
   rosrun lcc main  # 启动控制程序（需root权限时前缀加sudo）
   ```

2. **硬件连接验证**  
   - 确认IMU、关节编码器、电源等硬件连接牢固，无松动或接触不良。
   - 程序启动后，通过`imu.cpp`接口查看IMU数据（终端会输出`rotMatToRPY`姿态信息），确保roll、pitch、yaw值稳定（无跳变）。
   - 检查关节编码器数据：终端会打印电机目标角度与实际角度，确认两者偏差在合理范围（通常≤0.5°）。


二、状态切换与初始化流程
按以下顺序执行指令，完成机器人从断电到可运动的状态切换：

1. **退出闭环模式**  
   - 输入指令：`o`（小写字母o）  
   - 作用：断开控制器与电机的闭环控制，电机无动力输出，进入手动调试模式，避免启动初期误动作。  
   - 验证：终端会打印“MOTOR_DISABEL_FLAG”及电机角度信息，确认电机处于自由状态。

2. **进入闭环模式**  
   - 输入指令：`p`（小写字母p）  
   - 作用：激活PID与WBC控制闭环，电机开始响应控制指令，维持当前姿态。  
   - 验证：终端显示“MOTOR_ENABLE_FLAG”，电机角度稳定在当前位置（无明显晃动）。

3. **机械校准（抖动控制）**  
   - 输入指令：`[`（左方括号）  
   - 作用：启动抖动抑制算法，通过微小角度调整消除关节机械间隙，确保后续控制精度。  
   - 验证：电机轻微抖动后恢复稳定，终端打印的电机角度偏差缩小。

4. **进入算法控制模式**  
   - 输入指令：`]`（右方括号）  
   - 作用：切换至MPC与WBC算法控制，机器人开始根据传感器数据动态调整姿态。  

5. **姿态初始化**  
   按以下指令序列执行，完成机器人从蹲下到稳定站立的姿态调整：  
   - 输入`c`：机器人进入蹲下状态（关节角度固定为安全值，机身降低）。  
   - 输入`2`：从蹲下切换至固定站立状态（通过逆运动学缓慢起身，机身抬升）。  
   - 输入`3`：进入自由站立模式（平衡控制启动，通过WBC实时调整关节力，维持机身水平）。  
   - 输入`ikikii`：执行自定义姿态微调（根据预设逻辑优化足端位置，适配地形）。  

6. **激活全身动力学控制**  
   - 输入指令：`7`  
   - 作用：启用WBC（全身动力学控制），机器人可根据步态指令动态分配足端力，适应地形变化。  

7. **切换至步态模式**  
   - 输入指令：`.`（小数点）  
   - 作用：从站立状态切换至四足步态模式（根据预设步态参数运动，如trot或行走步态）。  

8. **数据保存**  
   - 输入指令：`T`（大写字母T）  
   - 作用：将当前状态数据（电机力矩、姿态、足端力等）保存至`log.txt`及相关文本文件，用于后续调试与分析。


三、操作注意事项
- 严格遵循指令顺序：未执行前序步骤（如未退出闭环模式直接进入站立）可能导致电机过载或姿态异常。
- 实时监控终端输出：若出现“电机角度偏差过大”“IMU数据异常”等提示，需立即输入`o`停止控制，检查硬件后重新启动。
- 紧急处理：遇到机器人倾倒风险时，立即输入`1`进入被动状态，切断电机动力，避免硬件损坏。
